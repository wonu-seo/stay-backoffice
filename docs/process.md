# 작업 프로세스 규칙

이 저장소의 모든 작업이 따르는 규칙이다. 스레드(Claude)와 로컬 Claude Code가 같은 파일을 본다.

## 기본 단위

작업 하나는 **스레드 1개 = 이슈 1개 = PR 1개 = 계획 문서 1개 = 브랜치 1개**로 1:1 대응한다.

- 여러 이슈를 PR 하나로 묶지 않는다. 예외는 이슈가 아주 작고 서로 강하게 붙어 있을 때뿐이다.
- 스레드는 이슈 단위로 연다. 검토, 계획, 기록, PR 리뷰가 모두 이슈 범위와 겹치기 때문이다.

## 묶는 방법

관련 작업은 PR이 아니라 이슈 위 단계에서 묶는다.

- **상위 이슈(Epic)**: 하위 이슈(sub-issue)를 둔다. 예) "예약 동시성 문제" 아래 "재현", "락 적용", "재측정"
- **마일스톤**: 로드맵 단계별로 묶는다.
- **설계 스레드**: 큰 주제는 Epic 설계만 논의하는 스레드를 따로 열고, 하위 이슈마다 스레드를 연다.

## 작업 흐름

1. **작업 제시**: 작업을 제시하면 스레드가 열린다.
2. **검토**: 스레드에서 선택지와 트레이드오프를 정리하고, 결정은 WU가 한다.
3. **이슈·계획 문서**: 이슈 템플릿으로 이슈를 만들고, `docs/plans/<이슈번호>-<slug>.md`에 계획을 쓴다.
4. **로컬 작업**: Claude Code와 코드 에디터로 전용 브랜치에서 작업한다.
5. **작업 기록**: `docs/records/<이슈번호>-<slug>.md`에 기록 형식대로 남긴다.
6. **푸시**: 브랜치를 GitHub에 올린다.
7. **PR 검토**: PR 템플릿에 계획·기록 링크를 넣고, 트랜잭션·동시성·N+1·인덱스·예외 처리·보안 관점으로 리뷰한다.
8. **머지 전 점검**: 기록이 남았는지 확인한 뒤 머지한다.

## 이름 규칙

| 대상 | 형식 | 예 |
| --- | --- | --- |
| 스레드·이슈·PR 제목 | `[type] 한국어 작업 내용` | `[feat] 객실 재고 차감 동시성 처리` |
| 브랜치 | `<type>/<이슈번호>-<영문-slug>` | `feat/12-room-stock-concurrency` |
| 계획 문서 | `docs/plans/<이슈번호>-<영문-slug>.md` | `docs/plans/12-room-stock-concurrency.md` |
| 기록 | `docs/records/<이슈번호>-<기록종류>-<영문-slug>.md` | `docs/records/12-perf-room-stock-lock.md` |

기록 종류: `design`(설계 결정), `ai`(AI 검증), `perf`(성능 개선), `incident`(장애 대응)

## 기록 형식

- **[설계 결정]** 상황 / 선택지 / 결정 / 이유 / 감수한 점
- **[AI 검증]** AI가 만든 것 / 발견한 문제 / 판단 근거 / 수정 내용
- **[성능 개선]** 측정 조건 / 개선 전 수치 / 원인 / 조치 / 개선 후 수치
- **[장애 대응]** 증상 / 발견 경로 / 원인 / 조치 / 재발 방지

측정하지 않은 수치는 "미측정"으로 쓴다. 시뮬레이션 결과를 실운영처럼 쓰지 않는다.

## GitHub 구성

기록과 작업 관리는 모두 GitHub에서 한다. 기록은 PR 리뷰가 가능하도록 Wiki가 아니라 저장소 `docs/`에 둔다.

| 기능 | 용도 |
| --- | --- |
| Milestones | 로드맵 단계별 묶음 (아래 표) |
| Issues + 하위 이슈 | 작업 / Epic 템플릿 사용, 빈 이슈는 막아 둠 |
| Labels | 아래 라벨 체계 |
| Projects 보드 | Todo / In Progress / Review / Done |
| PR 템플릿 | 이슈·계획·기록 링크, 리뷰 관점 체크, 머지 전 점검 |
| 브랜치 보호 | `main` 직접 push 금지, PR로만 머지 (승인 0명, 혼자 진행하므로) |

### 라벨

라벨은 영문 접두어로 그룹을 나눈다. 도메인 라벨은 실서비스가 아닌 시뮬레이션이라 두지 않는다.

| 그룹 | 값 |
| --- | --- |
| `type:` | feat / fix / refactor / perf / test / docs / infra / chore |
| `problem:` | concurrency / query-performance / external-failure |
| `record:` | design-decision / ai-verification / perf-improvement / incident |
| `epic` | 상위 이슈 표시 |

`record:` 라벨은 그 기록을 남긴 PR(과 이슈)에 붙인다. 완료 조건의 기록 개수를 라벨로 셀 수 있다.
