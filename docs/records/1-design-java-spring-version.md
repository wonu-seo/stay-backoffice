# [설계 결정] Java/Spring 버전과 개발 도구

- 날짜: 2026-11-16
- 관련 이슈: #1 (도구 설치와 버전 확인은 개발 환경 세팅 이슈에서 이어서 한다)
- 상태: 초안. 개발 환경 세팅을 진행하면서 수정한다.

## 상황

새 백오피스 프로젝트의 언어·프레임워크 버전과 개발 도구를 정해야 했다. 비용은 무료 도구를 기준으로 한다.

## 선택지

- Java 21 + Spring Boot 3.5
- Java 21 + Spring Boot 4.x
- Java 25 + Spring Boot 4.x

## 결정

Java 25 (LTS) + Spring Boot 4.x

## 이유

- 지원 기간이 가장 긴 LTS다.
- 가상 스레드를 외부 연동·타임아웃 문제에 활용할 수 있다.
- AI가 만든 예전 버전 방식의 코드를 검증하는 경험이 [AI 검증] 기록이 된다.

## 감수한 점

- 참고 자료가 적고, 라이브러리 호환 위험이 있다.
- 현업에 많은 Boot 3 환경과 차이가 있다.
- LTS가 아닌 버전(26, 27)은 지원 기간이 6개월이라 제외했다.

## 함께 정한 도구

| 항목 | 선택 | 도입 시점 | 이유 | 감수한 점 / 대안 |
| --- | --- | --- | --- | --- |
| 코드 에디터 | IntelliJ IDEA 무료 버전 | 환경 구성 | 빌드, 디버거, JUnit, 리팩토링은 무료 버전으로 충분 | Spring 전용 지원, HTTP Client, DB 툴, 프로파일러 없음. 아래 도구로 보완 |
| JDK 배포판 | Amazon Corretto 25 | 환경 구성 | AWS 배포 계획이 있어 운영 환경과 맞추기 쉬움 | Temurin도 가능 |
| 빌드 도구 | Gradle 9.1 이상 | 환경 구성 | Spring 생태계의 기본 선택, 실무에서 Maven보다 많이 사용 | Java 25 지원 버전 확인 필요 |
| DB | MySQL 8.4 LTS (로컬은 Docker Compose) | 환경 구성 | 실무에서 쓰던 DB의 현재 LTS. Docker로 배포 환경과 버전을 맞추기 쉬움 | - |
| DB 툴 | DBeaver | 환경 구성 | 무료, MySQL과 Redis(일부) 지원 | - |
| API 테스트 | Bruno | 환경 구성 | 요청을 파일로 저장해 커밋하고 PR로 리뷰 가능 | Postman보다 자료가 적음 |
| 부하 테스트 | k6 | 기준 측정 | 가볍고, 스크립트와 결과를 PR 기록으로 남기기 좋음 | JS를 약간 써야 함. Java를 원하면 Gatling |
| 프로파일링 | JFR + VisualVM | 성능 개선 | 무료이고 범용적으로 쓰는 도구 | IntelliJ 유료 프로파일러보다 불편 |
| 캐시 | Redis | 캐시가 필요한 문제를 재현할 때 | - | - |

## 확인 사항

설치 전에 확인한다. k6는 기준 측정 단계에서 부하 발생 도구와 서버를 다른 머신에 두도록 측정 환경을 함께 정한다.

- [ ] Java 25와 Spring Boot 4.x의 공식 지원 일정 확인
- [ ] Gradle의 Java 25 지원 버전 확인
- [ ] IntelliJ 무료 버전의 현재 배포 형태와 무료 범위 확인
