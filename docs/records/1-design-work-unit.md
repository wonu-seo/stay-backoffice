# [설계 결정] 작업 단위와 문서 위치

- 날짜: 2026-11-16
- 관련 이슈: #1

## 상황

스레드에서 검토하고 로컬에서 작업하는 흐름을 오가면서, 작업 단위와 문서를 어디에 둘지 정해야 했다.

## 선택지

- **A.** 여러 이슈를 PR 하나로 묶는다.
- **B.** 이슈 1개 = PR 1개로 두고, 묶음은 Epic·마일스톤으로 만든다.

문서 위치:

- **A.** Claude 문서(claude.ai 아티팩트)
- **B.** GitHub Wiki
- **C.** 저장소 `docs/` (마크다운)

## 결정

- 작업 단위: **B**. 스레드도 이슈 단위로 연다.
- 문서 위치: **C**. 계획은 `docs/plans/`, 기록은 `docs/records/`에 둔다.

## 이유

- 판단과 변경이 1:1로 추적되고, 리뷰 범위가 작아진다.
- 저장소 문서는 스레드와 로컬 Claude Code가 함께 볼 수 있다.
- 문서도 PR로 리뷰되고 커밋 이력이 남아, 그 자체로 "판단의 흔적"이 포트폴리오가 된다.
- Claude 문서는 보기 좋지만 저장소 밖에 있어 PR 리뷰와 이력 추적이 끊긴다. Wiki는 PR 리뷰가 안 된다.

## 감수한 점

- PR과 이슈 개수가 늘고, 작은 작업에도 문서·브랜치 관리 비용이 든다.
- 마크다운이라 Claude 문서보다 서식 표현이 제한된다.
